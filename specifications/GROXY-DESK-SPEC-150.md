# Groxy Desk v1.5.0 — Unified Windows title bar and silent background processes

**Status** Approved for implementation by the project owner on 2026-11-22.

**Release tier** Backward-compatible minor release affecting Groxy Desk only. The ten frozen sibling repositories and their contracts stay untouched.

## Silent Windows subprocesses

- Route subprocess creation in the desktop launcher and internal packages through one shared Go package that takes executable names and argument slices. Audit all `exec.Command` and `exec.CommandContext` sites, including test fixtures, and check for alternate process launch paths.
- Apply `applyDetachedWindow(cmd)` before starting a Windows child. Set `HideWindow: true` and add `CREATE_NO_WINDOW` (`0x08000000`), preserving any existing process attributes. Linux and macOS use a no-op. Preserve cancellation, launch errors, stdout, stderr, working directory, and environment. Keep the desktop launcher on the GUI subsystem and the standalone daemon on the console subsystem.
- Cover the actual process paths for GRAB check and format, workers, MCP, grabman, author tools, and PostgreSQL dump. SSH tunnel establishment, database inspection, and MariaDB snapshot operations already use in-process code. Check those workflows for transitive console creation during Windows acceptance. Include any Git executable caller discovered in the audit.

## Unified title bar

- Make the 32 CSS pixel `#desk-header` the single window title bar. Keep the 18 pixel emerald Groxy Desk logo, the File, Edit, View, Database, Browser, Tools, and Help controls, centered Command Search with Ctrl+K, and a Light/Dark theme toggle. Preserve the existing command search and menu actions. Keep the title bar visible across studios, including while the native research pane is open.
- Place `#desk-win-min`, `#desk-win-max`, and `#desk-win-close` at the far right. Use semantic buttons with accessible names and visible focus. Reflect the actual maximize or restore state in the icon and accessible name. Show the window controls only after the trusted native host handshake. The browser-hosted workbench retains its menus, command search, and theme toggle.
- Remove the Win32 caption and any DWM frame extension. Keep `WS_THICKFRAME | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_SYSMENU` and preserve native resize, drag-to-snap, double-click maximize or restore, and keyboard system commands. Use `WM_NCHITTEST` for DPI-aware edges and corners and route empty title-bar regions through native `HTCAPTION` behavior. Handle maximized bounds against the active monitor work area.
- Enable WebView2 non-client regions for the trusted workbench only. Mark the empty header as draggable and its interactive controls as no-drag using `app-region` and `-webkit-app-region`. Right-click on empty header space opens the native system menu using `GetSystemMenu(hwnd, false)` and `TrackPopupMenu`. Keep normal pointer behavior on the search and controls. Keep the research pane below the window header.
- Add the fixed `win_minimize`, `win_toggle_maximize`, and `win_close` commands to the existing WebView2 message policy. Validate both the sending document and the controller's current source against the exact trusted loopback workbench. Accept the three action messages without arguments. Use native window commands on the UI thread. Keep WebView2 host objects and research-pane messaging disabled per the existing isolation policy.

Implementation references: [WebView2 non-client regions](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2settings9?view=webview2-1.0.2849.39) and [Win32 custom window frame and hit testing](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe).
